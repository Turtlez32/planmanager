Overview

A self-hosted web service that stores, renders, and serves HTML plan documents generated by AI agents. Agents can upload new plans, retrieve them by slug URL, and update them mid-project via a REST API secured with API keys. The system has a single human admin (twadmin) who manages plans through a web dashboard protected by email/password login. There is no public registration — the admin account is seeded from environment variables on first boot.

Primary use case: When an AI agent starts a new project it POSTs the HTML plan to this service and receives back a public URL (plans.turtlez.au/p/<slug>). Other agents can fetch or update that plan at any time using the same URL + API key — no copy-pasting between sessions.
Auth model: Reading a plan requires no credentials — the slug URL is the access token (8-char random, unguessable). Writing or creating plans requires an API key (GUID) generated by the admin in the dashboard and given to each agent. There is no /auth/register endpoint — the attack surface is intentionally minimal.
Agent accounts: Exactly two API keys are provisioned — one labelled claude and one labelled codex. These are created by the admin on first setup and shared with each agent respectively. No other agents can POST to the API.

API Reference

Auth schemes: Browser routes use Authorization: Bearer <jwt> (obtained from login). Agent routes use Authorization: Bearer <api-key>. Public routes require no auth.

AUTH
POST/auth/loginpublic
Body: { email, password } → returns JWT. Only the seeded admin account can log in. No registration endpoint exists.
API KEY MANAGEMENT (JWT required)
GET/api-keysjwt
List all API keys for the authenticated user (hashes hidden)
POST/api-keysjwt
Body: { label } → generates key, returns raw key once
DELETE/api-keys/:idjwt
Revoke a key by ID
PLANS — BROWSER (JWT required)
GET/plansjwt
List plans. Query params: ?q=search+term · ?tag=react · ?limit=20&offset=0
POST/plansjwt
Multipart: title, description, tags, html (file or raw string) → returns plan with slug
GET/plans/:slugjwt
Returns plan metadata + HTML content
PUT/plans/:slugjwt
Body: { title?, description?, tags?, html? } — partial update supported
DELETE/plans/:slugjwt
Deletes metadata row and HTML file from disk
PLANS — AGENT API (API key required)
GET/api/plansapi-key
List all plans. Returns [ { slug, title, description, tags, updated_at, url } ]
GET/api/plans/:slugapi-key
Returns full plan: metadata + html field with file contents
POST/api/plansapi-key
Body: { title, description, tags, html } → creates plan, returns slug + public URL
PUT/api/plans/:slugapi-key
Replace or patch HTML for an existing plan. Body: { html, description?, tags? }
PUBLIC
GET/p/:slugpublic
Serves the raw HTML plan file — linkable from any browser or agent

nginx Configuration

nginx terminates SSL and routes by path prefix. API traffic (/p/, /api/, /auth/, /plans, /api-keys) goes to the Fastify container. Everything else goes to Next.js.

# nginx.conf

upstream planmanager_api {
  server api:3001;
  keepalive 32;
}

upstream planmanager_web {
  server web:3000;
  keepalive 32;
}

# Redirect all HTTP → HTTPS
server {
  listen 80;
  server_name plans.turtlez.au;
  return 301 https://$host$request_uri;
}

server {
  listen 443 ssl http2;
  server_name plans.turtlez.au;

  ssl_certificate /etc/letsencrypt/live/plans.turtlez.au/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/plans.turtlez.au/privkey.pem;
  include /etc/letsencrypt/options-ssl-nginx.conf;
  ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;

  # Security headers
  add_header X-Frame-Options SAMEORIGIN;
  add_header X-Content-Type-Options nosniff;
  add_header Referrer-Policy strict-origin-when-cross-origin;
  add_header Strict-Transport-Security "max-age=63072000; includeSubDomains" always;

  client_max_body_size 10M; # allow large HTML plan uploads

  # Public plan viewer → API
  location /p/ {
    proxy_pass http://planmanager_api;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }

  # Agent API → API
  location /api/ {
    proxy_pass http://planmanager_api;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }

  # Login → API
  location /auth/ {
    proxy_pass http://planmanager_api;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }

  # Dashboard plans API → API
  location /plans {
    proxy_pass http://planmanager_api;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }

  # API key management → API
  location /api-keys {
    proxy_pass http://planmanager_api;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }

  # Everything else → Next.js frontend
  location / {
    proxy_pass http://planmanager_web;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }
}

docker-compose.yml

Two services: api (Fastify) and nginx (SSL + static web + API proxy). The web SPA is baked into the nginx image at build time.

# docker-compose.yml
services:
  api:
    build:
      context: ./apps/api
    env_file: .env
    environment:
      - NODE_ENV=production
    volumes:
      - plandata:/data
    expose:
      - "3001"
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://localhost:3001/health"]
      interval: 30s
      timeout: 10s
      retries: 3
    restart: unless-stopped

  nginx:
    build:
      context: .
      dockerfile: Dockerfile.nginx # multi-stage: builds web SPA then copies into nginx
      args:
        VITE_API_URL: https://plans.turtlez.au
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - /etc/letsencrypt:/etc/letsencrypt:ro
    depends_on:
      api:
        condition: service_healthy
    restart: unless-stopped

volumes:
  plandata:
Dockerfile.nginx — multi-stage: Stage 1 builds apps/web with Vite, Stage 2 is nginx:alpine that COPYs the dist/ output and the nginx.conf. The web SPA is shipped inside the nginx image — no separate web container needed.

Local Development Workflow

Run both apps directly with hot reload — no Docker needed for day-to-day development.

# Install all workspaces from repo root
npm install

# Terminal 1 — Fastify API (vite-node, hot reload, port 3001)
cd apps/api && npm run dev

# Terminal 2 — Vite + React SPA (HMR, port 5173)
cd apps/web && npm run dev

# apps/web/.env.local — used only in local dev
VITE_API_URL=http://localhost:3001
CORS in dev: The Vite dev server runs on http://localhost:5173. The Fastify CORS allowlist already includes http://localhost:3000 — update it to include http://localhost:5173 for local dev, guarded by NODE_ENV !== 'production'.

Instructions for Remote Agent

How to start building this project

  1. Read this entire document before writing any code.
  2. Complete Phase 0 (GitLab + SSH setup) before writing any application code.
  3. Create the monorepo structure exactly as shown in the File Structure section.
  4. Build Phase 1 first — get the DB schema and Fastify server booting before touching auth or routes.
  5. Follow phases in order. Each phase's tasks are numbered globally — use them as checkboxes.
  6. Use TypeScript strict mode throughout. No any types.
  7. Package manager is npm. Use npm workspaces. Do not use pnpm or yarn.
  8. API backend uses Vite (vite-node) for dev and build. Frontend uses Vite + React 18 with React Router v6 and Tailwind CSS.
  9. Use better-sqlite3 (synchronous) for the DB — not an async ORM.
  10. All HTML files are stored on disk, not in the DB. The DB only stores metadata and the file path.
  11. There is no /auth/register endpoint. The admin user is seeded from ADMIN_EMAIL + ADMIN_PASSWORD_HASH env vars during migration on first boot.
  12. API key middleware must hash the incoming Bearer token with SHA-256 and compare to the stored hash — never compare raw strings.
  13. The /p/:slug public route must work with no auth — the slug IS the access token for reading a plan.
  14. Agents read plans via the public /p/:slug URL. Agents write/create plans via /api/plans with a Bearer API key.
  15. Exactly two API keys exist: one for Claude (claude), one for Codex (codex). Do not create additional keys unless instructed.
  16. JWT tokens are stored in localStorage on the frontend. The fetch wrapper in lib/api.ts attaches them automatically.
  17. To deploy a new version, run bash scripts/update.sh from /opt/planmanager on the VPS. This does git pull + docker compose rebuild.
  18. Log level is controlled by LOG_LEVEL env var. Fastify uses pino — all logs go to stdout, captured by Docker.
  19. After completing each phase, run the server locally and verify the routes work before moving on.
  20. When done with all phases, provide a curl cheatsheet for common agent operations.

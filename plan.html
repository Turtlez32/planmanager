Overview

A Vercel-hosted MCP server that stores, sanitizes, and serves HTML plan documents created by AI agents. Claude and Codex both run on the same Linux machine and connect to the remote MCP endpoint with individual bearer tokens. Desktop apps on macOS act as triggers — sending prompts to the remote agents — but the agents themselves live on Linux. No REST API. No local bridge. No dashboard. No VPS. No Docker.

Confirmed: Codex sends Authorization: Bearer <token> on POST /mcp directly to a remote HTTP MCP endpoint. Tested 2026-06-15 using bearer_token_env_var in ~/.codex/config.toml. Both agents use the same /api/mcp endpoint with different tokens — no bridge needed.
Content format: Plans are stored as HTML (preserving full styling and layout). The viewer sanitizes HTML server-side through a strict allowlist before serving, stripping scripts, event handlers, iframes, and forms while keeping all structural and presentational markup.
Ownership: Each plan records which agent created it (owner_principal). Both agents can read all plans. Each agent can only update or delete plans they own. An optional admin token can override ownership for maintenance.

Database Schema

One table. No users table. No API keys table. Identity is inferred from the bearer token at request time.

Auth Model

Principals and Scopes

CLAUDE_MCP_TOKENclaudeplans:read · plans:create · plans:update-own · plans:delete-own
CODEX_MCP_TOKENcodexplans:read · plans:create · plans:update-own · plans:delete-own
ADMIN_MCP_TOKENadminplans:read · plans:create · plans:update-any · plans:delete-any (hard)
Implementation: lib/auth.ts extracts the Bearer token and compares against all three env vars using crypto.timingSafeEqual. Returns { principal, scopes } or throws 401. Ownership check in PlanService: if scope is update-own, verify plan.owner_principal === principal before proceeding.
Token storage on Linux: Tokens live in environment variables only — never in git, chat history, or config files. Claude: token in ~/.claude/settings.json headers (already excluded from git). Codex: token in ~/.zshenv as PLANMANAGER_CODEX_TOKEN, referenced by bearer_token_env_var in config.

MCP Tools Reference

All five tools are available to both claude and codex principals. Write operations enforce ownership — agents can only modify plans they created unless the admin token is used.

create_plan scope: plans:create
Stores HTML in Vercel Blob, saves metadata to Postgres. Sets owner_principal and revision = 1.
Input: { title: string, description?: string, tags?: string[], html: string }
Returns: { slug, url: "https://plans.turtlez.au/p/<slug>", owner_principal, revision }
update_plan scope: plans:update-own (or update-any for admin)
Replaces HTML in Blob, updates metadata, increments revision, sets updated_by and updated_at. Rejects with 403 if caller is not the owner (unless admin).
Input: { slug: string, html: string, description?: string, tags?: string[] }
Returns: { slug, url, revision, updated_by, updated_at }
get_plan scope: plans:read
Returns metadata for a plan. HTML is at the public URL — agents fetch it directly from there if needed.
Input: { slug: string }
Returns: { slug, title, description, tags, url, owner_principal, created_by, updated_by, revision, created_at, updated_at }
list_plans scope: plans:read
Lists all active (non-deleted) plans, newest first. Optional search via ILIKE on title, description, tags.
Input: { search?: string, tag?: string, owner?: string, limit?: number }
Returns: [ { slug, title, description, tags, url, owner_principal, revision, updated_at } ]
delete_plan scope: plans:delete-own (soft) · plans:delete-any (hard, admin only)
Default: soft delete — sets deleted_at, plan no longer appears in lists or viewer. Blob is retained. Admin hard delete: removes the Postgres row and deletes the Blob file permanently.
Input: { slug: string, hard?: boolean }
Returns: { deleted: true, slug, mode: "soft" | "hard" }

HTML Sanitization + Viewer

Plans are stored as raw HTML (preserving full styling, layout, and structure). Before serving at /p/:slug, the HTML is passed through sanitize-html with a strict allowlist. The viewer sets security headers to prevent script execution and framing.

sanitize-html allowlist (lib/content.ts)

Allowed tagsAll structural + presentational HTML: div, p, h1–h6, span, ul, ol, li, table, thead, tbody, tr, th, td, code, pre, section, header, footer, strong, em, a, br, hr, img, style
Allowed attrsclass, id, style on all tags. href on a (http/https only). src on img (https only).
Stripped alwaysscript, iframe, form, input, button, object, embed, all on* event handlers, javascript: URLs

Viewer response headers

Content-Security-Policydefault-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' https: data:; script-src 'none'; object-src 'none'; form-action 'none'; frame-ancestors 'none'; base-uri 'none'
X-Content-Type-Optionsnosniff
X-Frame-OptionsDENY
Referrer-Policyno-referrer
Never: serve the raw HTML stored in Blob directly to a browser without running it through the sanitizer first. The sanitizer is the only thing standing between agent output and script execution on plans.turtlez.au.

Instructions for Building Agents

How to build this project

  1. Read this entire document before writing any code.
  2. Complete Phase 0 Vercel setup before writing application code — Postgres and Blob env vars must exist before the code can run.
  3. Build phases in order: scaffold → library layer → MCP server → viewer → deploy.
  4. TypeScript strict mode throughout. No any types.
  5. Use @vercel/postgres and @vercel/blob — do not use raw pg or node-fetch.
  6. Auth is three env var comparisons using crypto.timingSafeEqual — nothing more complex is needed.
  7. Ownership enforcement belongs in lib/plans.ts, not in the MCP tool handlers. Handlers pass through { principal, scopes } and let PlanService reject.
  8. The sanitizer in lib/content.ts must run on every viewer response. Never serve raw Blob content directly to a browser.
  9. Soft delete is the default. Hard delete (admin only) removes the Postgres row AND the Blob file.
  10. After Phase 3, test locally with vercel dev and a local .env.local before pushing.
  11. Future deploys: git push origin main — Vercel auto-builds from GitLab.
  12. Both Claude and Codex run on the same Linux machine. Desktop apps on macOS are triggers only — all agent compute happens on Linux.
